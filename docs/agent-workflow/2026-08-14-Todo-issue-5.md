## 🏛️ Architecture & Decisions
- **Conventions followed:** Strict `Controller → TodoRepository → TodoServiceInterface → TodoService → Model` layering; filtering added ONLY in `TodoService::paginate()` (the sole layer that touches the model). Input validation via a new FormRequest returning `config('todo.messages')`; named-param calls end to end; zero hardcoding; PHPUnit + RefreshDatabase.
- **Key decisions:**
  - New `IndexTodoRequest` FormRequest with `['completed' => ['sometimes','boolean']]` — matches every other input path in the project (Store/Update requests) and lets Laravel auto-throw the 422. Rejected inline `$request->validate()` (controller does dispatch only) and manual `abort(422)` (reinvents the `boolean` rule, risks a hardcoded message).
  - `completedFilter(): ?bool` helper returns a strict tri-state (true/false/null) using `array_key_exists` on `validated()` — preserves the absent-vs-present distinction that drives the unchanged-when-absent behavior. Explicit `(bool)` cast because the `boolean` rule passes query strings `"1"`/`"0"` through as strings.
  - Service applies `->when(! is_null($completed), fn ($q) => $q->where('completed', $completed))->latest()->paginate($perPage)` — the `->latest()->paginate($perPage)` order is byte-for-byte unchanged, so the pagination envelope and response shape are identical.
  - `?bool $completed = null` default on Repository/Interface/Service keeps all other `paginate()` callers untouched.
  - Reused the existing `completed.boolean` message key — no new `config/todo.php` key (DRY).
- **Assumptions / trade-offs:**
  - Single scalar read-filter uses the FormRequest helper, not a new `TodoFilterData` DTO (the project's DTO is for persisted write payloads).
  - `?completed=` (empty string) is treated by the `boolean` rule as `false`, not a full listing — acceptable per the "not a silent full listing" requirement; left untested as out of the stated scope.
- **Mismatches found:** None — the codebase and CLAUDE.md agree on the layered architecture for this change.
